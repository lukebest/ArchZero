# 2609.00450: HBQ: Hierarchical Scaling Block Quantization

- arXiv: [2609.00450](https://arxiv.org/abs/2609.00450) · PDF: [arxiv.org/pdf/2609.00450](https://arxiv.org/pdf/2609.00450)
- Venue: MICRO 2026 (authors’ line, p.1). 15 PDF pages. Cornell (Chen, Han, Mun, Hyun, Abdelfattah, Seo) + Intel (Raha, Agarwal, Anders).
- Domain tag: LLM decode / cache
- One-line hardware fact: 28 nm place-and-routed weight-stationary systolic (4096 MACs, 500 MHz, 174 kB buffers) that does W4A5 two-level block quant with 2-bit significand L2 scales, optional MXINT8 psum compression, and the same PE for projections and quantized attention.

## 四视角独立批评

### 微架构

HBQ is a *datapath* paper. The algorithm exists to justify an extra dequant stage on a large-block PE.

**Baseline PE they DSE on (Fig. 2, p.3).** For block size `B`: (1) `B` muls, FP2FX if needed; (2) lossless `B`-to-1 fixed-point adder tree; (3) dequant by FP8 mul or PoT shift; (4) FP accumulate across blocks. That four-stage PE *is* the hardware object of Section IV. They synthesize it at TSMC 28 nm / 500 MHz and normalize area/energy per MAC (p.3). RTL of the baseline is claimed at an anonymous GitHub [21] (p.3).

**DSE conclusions they then freeze (p.5).** FP8-scale (they use unsigned `ue5m3`, no per-tensor scale, Table II p.3) beats PoT once `B` is 64–128 because the FP mul amortizes (Fig. 3). Element format: 2-bit exponent (E2M*) beats fat-exponent FP8 and INT because the intra-block range is already narrow (Fig. 4–5). Activation: A5 is the knee vs. A4/A8 (Table III, Fig. 6–7). Large `B` (≥32, they take 128) wins TOPS/mm² and weight EBW and loses PPL. KV block size, when W/A are NVFP4, also loses PPL as `B` grows (Table IV). Those are *format and grouping* choices, not mechanisms.

**HBQ mechanism (Section V, p.5–7).** L1 block `B_b` with FP8 scale `s_b` (B=128). Each micro-block `U_{b,u}` gets a 2-bit L2 scale `α_{b,u}`. Effective scale `s̃ = s_b · α` (Eq. 5). Significand scaling: `α_SIGx(c) = 1 + c / 2^x`, `c ∈ {0,…,2^n−1}`, `n=2` (Eq. 8, p.6). They pick `x` by operand class: SIG1 for activations/KV, SIG2/SIG3 mixture for weights. Weight side: per L1 block, offline try SIG2 and SIG3, keep the lower MSE, store a 1-bit selector `k` (p.6). No calibration set for that choice. MAC (Fig. 9(b), p.7): μB-to-1 FX adder tree → L2 dequant from `(c_a, c_w, k)` → FX2FP → L1 dequant with `(s_a, s_w)` → FP block psum. Everything before L1 dequant stays fixed-point because `α` lives in a tiny integer range. HBQ-E: μB=32, +~9% area vs. B128 one-level, EBW +0.13b. HBQ-A: μB=8, more scale overhead, AWQ-like PPL (Fig. 10–11, Table V).

**Accelerator (Section VI, p.8).** 32 PEs × 128 MAC = 4096 MAC/cycle, weight-stationary, 41.5 kB input + 132 kB psum = 174 kB, `T_k=512`, `T_o=128` (p.8, Fig. 12–13). KV is treated *as weight* (4-bit) so QKᵀ and SV reuse the same PE (p.8). Partial-sum path: 32 FP16 psums quantized to 32 MXINT8 (PoT-scale INT8, block 32 = N_PE) to double psum capacity, dequant to FP16 for the add, requant on writeback (p.8). Intra-`B` reduction stays lossless FX; the lossy step is once every `M/B` along the reduction dim (p.8). Online quantizer: 3-stage pipe (L1 scale, L1 quant, L2 quant), 128 activations/cycle, 4.0% of 623 kμm² vs. NVFP4’s 3.0% (Table VIII, p.9). Softmax / RMSNorm / RoPE are *assumed* on an auxiliary FP16 SIMD (p.9).

**Mechanism vs policy.** Mechanism: two-level dequant in the PE; 2-bit SIG decode; 1-bit `k`; MXINT8 psum quant/dequant around the FP16 adders; unified 4-bit KV-as-weight path. Policy: B=128, μB ∈ {8,32}, SIG x per tensor class, W4A5, ue5m3, E2 element formats, MXINT8 vs. MXFP8 for psums, tile sizes.

**What is not hardware.** “Hierarchical” in VSQ/MicroExponent is a different grouping (Table V, p.8); they are right that those papers froze `B=16`. Rotation methods (QuaRot/SpinQuant) are discussed as competitors, not instantiated (p.12–13). There is no NoC, no DRAM controller, no cache hierarchy — “off-chip DRAM” is a box (Fig. 12).

### 负载

They actually ran more *model quality* than the three CIM papers combined, and still a narrow *system* load.

Accuracy suite: WikiText-2 PPL and 0-shot WinoGrande+PIQA on Llama-2-7B / 3-8B / 3.1-70B / 3.2-3B, Qwen2.5-3B/7B, Mixtral-8x7B (Table IX, p.10). Reasoning: GSM8K 8-shot, HumanEval, MMLU 5-shot on Llama 3.1-8B-Ins / 3.2-3B-Ins, with and without KV quant (Table XI, p.10). Long-gen case: DeepSeek-R1-Distill-Llama-8B, GSM8K+MATH500, 512 in / 8k out / **batch 64**, iso-accuracy vs. MXFP/NVFP (Table XII, p.12). System energy: context 2048, several dense models, KV quant on (Fig. 16, p.11). Iso-area speedup at seq 1k/4k/16k (Fig. 18, p.13). Power SAIF from Llama3-8B WikiText-2 (p.3, p.9). That is a serious PTQ bake-off.

What it is *not*. Mixtral-8x7B is a PPL/0-shot row (Table IX), not an MoE router/expert-memory experiment on the systolic. Prefill-heavy vs. decode-heavy is a *recommendation* (HBQ-E for prefill, HBQ-A for decode/KV-heavy, p.10–11) backed by a ~3% extra reasoning drop for HBQ-E once KV is quantized (Table XI) — not by a serving trace. Long-gen uses one distilled 8B at B=64 (p.12). No continuous batching, no paged KV, no speculative decoding, no 128k context. WikiText PPL is still the DSE objective (Section IV); they know Llama-3 is “notably harder to quantize” than Llama-2/OPT (p.9) and still steered the Pareto on Llama3-8B PPL (Fig. 1, Fig. 6).

Baseline fairness is better than CIM-vs-H100, and still messy. WoQ: AWQ quality + AxCore PE area (they did not have 70B AWQ PPL, Table IX blank). BQ: MXFP, NVFP, Amove-Aggr, VSQ, MicroExponent, MicroScopiQ, MANT — several only have Llama-2 PPL because “those papers never ran Llama-3” (p.9). MANT area is W4A8 because the PE cannot do W4A4 (Table IX note). MicroScopiQ PE uses “aggressive bit truncation” they refuse to trust (p.9, p.11). Amove energy excludes its decompression module (p.11). Iso-PPL GPU-less speedups allocate different MAC counts in the same die (p.12). DRAM is 4 pJ/bit [48][49] for everyone (p.11). So the 1.6–3.3× system energy and 1.5–3× speedup (abstract) are *same-accelerator-template* comparisons, not measured servers.

The skeleton inside the quality tables: MXFP4 W4A4/KV4 on reasoning is a massacre (27.5 avg vs. 65.9 FP16, Table XI). NVFP W4A4/KV4 is 53.4. HBQ-A W4A5/KV4 is 60.7. They *need* KV quant to claim “unified end-to-end.” Without KV quant, HBQ-A vs. AWQ is a wash on GSM8K (83.0 = 83.0) and a hair worse on MMLU (p.10). The abstract’s “W4A16-level accuracy using only W4A5” is the *no-KV* column, and Table I’s PPL 6.52 vs. AWQ 6.55 is also “without KV quantization for fair comparison” (Table I footnote). Read the footnotes.

### 仿真方法学

This is the only paper of the four with a place-and-routed prototype (Innovus, Arm SRAM compiler, 28 nm, 500 MHz, PrimeTime+SDF+SAIF on real WikiText traffic) (p.9, Fig. 15). PE-level DSE is synthesis of their Fig. 2 PE (p.3). Psum accuracy is custom CUDA kernels that mimic FP16+MXINT8 accumulation (Table VII, p.9). Quantizer is also synthesized (Table VIII). That is a real hardware methodology for a *GEMM island*.

What is still paperware. “System energy” (Fig. 16) = PrimeTime compute + compiler SRAM access energy + `bits × 4 pJ`. No DRAM timing, no bank conflict, no HBM vs. LPDDR, no NoC. Iso-area speedup (Fig. 18) is a MAC-count realloc under a fixed buffer — a spreadsheet over the WS dataflow in Fig. 13. Frequency sweep (Fig. 17) compares 2-cycle BQ vs. 3-cycle HBQ and a “-PL” BQ with an extra pipe; at 500 MHz they say FP accumulate still dominates so the extra stage is not a win for BQ (p.12). Long-gen Table XII *assumes* 512/8k/B=64 and iso-area MAC counts — not a measured decode loop. Auxiliary SIMD for softmax/RoPE is excluded from the 623 kμm² (p.9). Offline weight SIG selection cost is “no calibration” (p.6) but still a per-block MSE pass they do not time.

Compared to the NUS CIM papers: you can reproduce a PE and a layout here; you cannot reproduce a server. Compared to 2609.01084: they *show* the PPL tables that paper omitted. Still no taped-out chip, no GPU wall-clock, no gem5.

### 工业可行性

28 nm, 500 MHz, 4096 MAC, 0.88 mm²-class island (920×960 μm, Fig. 15) is a prototype PE array, not an inference SoC. Product GPUs they shadow-box (NVFP4, MXFP) live on 4 nm-class Tensor Cores with a software stack. HBQ’s deployment story is “direct-casting, no GPTQ required, beats QuaRot/SpinQuant PPL at W4A4 without rotation” (p.13) — attractive — plus an online quantizer after every FP16 nonlinearity (p.9). That quantizer and the SIMD are the tax a real SoC pays every layer, every decode step, on the Q and S tensors *after RoPE / after softmax* (p.10). They emulate that in the quality tables; they do not floorplan it.

Yield/process: 28 nm is easy and also the wrong generation for the TOPS/W they will be asked to beat. SIG decode and MXINT8 psum are small (Fig. 15 says psum quant overhead is “negligible,” p.11). The industrial risk is not the L2 mux; it is (1) W4A5 packing (“layout-misaligned” 5-bit, packed to byte groups, p.4–5), (2) per-block 1-bit `k` + 2-bit α streams in the memory subsystem, (3) KV-as-weight requiring the same block grouping on attention as on projections, which fights “advanced” KV methods that want pre-RoPE, per-channel, non-uniform types (p.10), (4) Mixtral as a quality row with no expert-offload story, (5) batch-64 long-gen as a slide, not a scheduler.

A chief architect would take the DSE (A5, E2, large B, FP8-scale) as *format guidance* and the P&R PE as evidence the L2 stage is cheap. They would not accept 2.3×/4.6× vs. AxCore (p.11) as a product claim against AWQ-on-GPU. They would also notice Table XIII (p.12): going B=128 *hurt* PPL (+0.31) and *cut* energy (−36.5%); L2 SIG *bought the PPL back* (+9.1% area, +10.7% energy vs. that cheap B128); MXINT8 psum then *gave 16.4% system energy back* at +0.01 PPL. The closet: the big win is “use a big block,” and HBQ is the apology.

## Master Class

1. **The Real Abstract** — A MICRO 2026 PTQ+ASIC paper: they swept block quant formats on a 28 nm PE, decided large blocks and 5-bit E2 activations sit on a better Pareto than NVFP4/MXFP4, then added a 2-bit significand L2 scale (different `x` for weights vs. activations) so B=128 does not destroy PPL. They P&R’d a 4096-MAC weight-stationary array, quantized psums to MXINT8 to enlarge the WS tile, and ran W/A/KV through one datapath. Quality tables are real; “system” 1.6–3.3× energy is a 4 pJ/bit DRAM model on that island.

2. **The Rashomon Synthesis** — Microarch and simulation *agree* this is the most concrete hardware of the four papers (P&R, SAIF, CUDA psum kernels) — then split on whether Fig. 16 is a system result. Workload and industry *agree* the unified W/A/KV story is the product pitch — then split: workload points at Table XI (KV quant is where reasoning dies for MX/NVFP and still sags for HBQ); industry points at the missing SIMD and 28 nm. Microarch is slightly cynical: Table XIII says large `B` did the efficiency work and SIG is a patch. Workload is less cynical about SIG (Table VI: SIG beats PoT/INT on PPL) and more cynical about “WoQ-level” (Table I footnote: no KV). The core tension: abstract language is “first to achieve WoQ-level accuracy while quantizing weights and activations” (p.13); the fair WoQ comparison *excludes* the KV/psum path that makes the accelerator unified (Table I, Table XI).

3. **The Magic Trick** — Make the block so large that dequant and FP accumulate become cheap, then buy back the error with a 2-bit scale that is only a significand nudge (`1 + c/2^x`), not another exponent.

4. **The Skeleton in the Closet** — “W4A16-level with W4A5” is without KV quant (Table I footnote, Table XI top). System energy uses 4 pJ/bit and a WS spreadsheet (p.11). Softmax/RoPE SIMD is off-chip to the claim (p.9). Amove/MANT/MicroScopiQ comparisons are incomplete by the authors’ own notes (p.9, p.11). Progressive ablation: B=128, not L2, is the efficiency cliff (Table XIII). RTL link is anonymous (p.3). 28 nm vs. the GPU formats they plot against.

5. **可提取的问题线索**

1. Block quant’s efficiency knob is block size: larger blocks amortize scale storage, dequant, and accumulate, but widen intra-block dynamic range and lose accuracy. (p.1–2)
2. Deployed formats freeze that knob small — Microscaling uses PoT scales over blocks of 32, NVFP4 uses FP8 scales over blocks of 16 — leaving dequant/accumulate under-amortized. (p.2)
3. Weight-only 4-bit paths still need a separate full-precision attention datapath if KV stays unquantized, so projection and attention do not share one pipeline. (p.2)
4. On Llama3-8B WikiText, FP16 PPL is 6.14, a strong weight-only point is 6.55, and NVFP4 is 6.88 — that gap is the accuracy price of a unified low-precision datapath (Table I footnote: without KV quant). (p.1)
5. Normalized PE area vs. FP16 is ~0.16 for that weight-only design and ~0.07 for NVFP4 at 4-bit weights; in batched datacenter decode, TOPS/W and TOPS/mm² dominate. (p.1–2)
6. Prior format sweeps treat block size as a fixed control and often omit joint area, energy, and end-to-end PPL, so the accuracy–efficiency Pareto of block quant is still unclear. (p.2)
7. At W4A4B16 on WikiText-2, Llama3-8B PPL spans 11.89 (e4m3, no per-tensor scale) down to ~6.87–6.88 depending on the FP8 scale encoding — the scale format is first-order. (p.3)
